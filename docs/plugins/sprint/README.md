# 內建的 sprint 插件（`docs/plugins/sprint/`）

給兩週一個 sprint、工單在 Jira、sprint 用**標籤**（例如 `Sprint7`）標的人。Python 3 標準庫，面板單檔。

1. 安裝：`scripts/install-plugin.sh docs/plugins/sprint`，設定頁「插件 → 重新載入」。
2. Jira 帳號：`~/.config/atlassian/netrc` 一行 `machine <站台> login <email> password <API token>`（跟其他用 netrc 的工具共用；插件不會把 token 存到別處）。
3. 面板「設定」分頁：站台、專案 key（可多個，逗號分開）、抓單用 JQL（預設 `project in ({projects}) AND labels = "{label}" AND assignee = currentUser()`）、估點欄位 id、實際點數欄位 id（Jira 沒有這個欄位就留空，寫回鈕就不出現）、每點小時數（預設 8）、回顧 Markdown 資料夾、整理回顧的 session 要開在哪。
4. 「總覽」分頁：建 sprint（標籤要跟 Jira 一樣，起訖日期給 burndown 用）→「同步 Jira」（JQL 查不到、手動加進來的單也一起重抓；「Sprint 資訊」裡的「重抓並清掉」讓 sprint 等於 JQL 結果）。狀態色照 Jira 的狀態分類：待辦灰、進行中藍、完成綠（自訂狀態屬於哪類由 Jira 工作流程決定）。上排五張數字卡（「待處理點數」＝未完成的估點，跟從今天到結束日的容量比：週一到週五、假日不扣，一個工作日 = 8 小時 ÷ 每點小時數 點；超過就紅字，整個 sprint 排的點數超過容量另標「排了 X / 容量 Y 點」；估 0 點的單在面板各處都算「未估點」）、任務分類與剩餘點數圖，下面是工單表：「投入」寫成「6h00m · 0.75 點」（點數＝投入時數 ÷ 每點小時數，就是實際點數，不能手動改；以前填過的覆寫值不再用），點一下在那列底下展開各類工時（session 自動記的叫「Session」——同一個 session 可能先盤點再實作，不替它猜種類；手動時段照種類）與本 sprint 每一筆手動時段的備註，上方「投入」數字卡點一下展開整個 sprint 的；「剩餘」是估點換成時數減掉已投入（綠／黃／紅照剩餘比例，超過就紅字「超 …」）；換狀態走 Jira transition；「＋」在那張單底下展開「補記時間」表單，補實體會議／討論；「寫回」把這張單所有投入（含之前的 sprint，跟「剩餘」同一個基準）換算的點數寫進設定的欄位。每列最前面的 ☆／★ 是重點標記，只存在本機（`tickets.json`），不寫回 Jira；點 ★、單號、狀態、估、剩餘、投入的標題排序（點 ★ 是有星號的排前面），再點反向，沒有值的排最後，排序不記住（重開面板回到原順序）。打到一半的欄位切分頁、面板重畫都不會丟。節奏：一期兩週，週一開始、第二個週日結束；最後那一週的週四是 review 日、週五是 planning 日（滑到標題旁的日期上會寫；手填的結束日早於週四就用結束日）。「建下一期」預填下一期的標籤（結尾數字加一，`Sprint09`→`Sprint10`；結尾不是數字就留空）、開始日（現期結束後的第一個週一）與結束日（加 13 天），都可以改；新的一期在 Jira 工單貼上標籤並同步前是空的。開始日還沒到就建的那一期不會馬上切過去，到它開始那天 Cubi 自動切一次，之後手動切回舊的不會再被拉走。建立或改日期時跟別期重疊會被拒。第一個 sprint、或還沒有日期的那一期，面板會照設定的「節奏錨點」（某一期開始的週一；預設留空，留空就不預填）算出包含今天的那兩週並預填，按儲存才生效。剩餘點數圖的理想線只在上班日下降、週末持平、最後一個上班日歸零。結束日是週五而下一期隔週一才開始的舊期，面板會提醒一次把結束日改成週日，否則那個週末的工時不算進任何一期。估點可以直接在工單表的「估」那格改：按 Enter 或離開那一格就寫回 Jira 的估點欄位，寫成功面板才跟著變（Jira 是準的，寫不進去就回到原值並顯示 Jira 的錯誤）；要是大於 0 的數字（全形數字也行，逗號、中間有空白、`1e3` 不行），清空代表未估點，不能填 0。設定頁填了「實際時數欄位」（Jira 上放實際時數的數字欄位）之後，每列多一顆「寫回時數」（沙漏）：把這張單所有投入（含之前的 sprint，計時、手動、session 自動記的都算）換成小時、四捨五入到小數兩位，蓋掉那個欄位原有的數字，別人手填的也會被蓋掉；還沒有投入的單不能寫。這兩個寫回連 Jira 的那幾秒不佔著資料檔，資訊窗與計時照常；寫回的單號必須是面板已經認得的工單。設定頁再打開「自動寫回時數」（預設關）的話，不用按沙漏：停止計時、新增／修改／刪除手動時段時，那張單先記成「等寫回」，Cubi 每分鐘的定時執行替最多 3 張寫進 Jira（每張等 Jira 5 秒，累計超過 10 秒就留到下一分鐘），寫的是當下的總投入時數，刪到沒有時數就寫 0；session 自動記的時段變長不算觸發，下次觸發或按沙漏時一起寫進去。連不上或逾時會一直重試；Jira 明確拒絕（沒有編輯權、欄位不在畫面上、查無此單）就停，總覽最上面顯示「N 張時數尚未寫回」與最後一次錯誤，按「重試」再排一次，那張單之後有新的工時也會再試。注意它覆蓋的是「這台機器記到的時數」：兩個人對同一張單都開著自動寫回會互相蓋掉。在 Jira 被刪掉（或你不再有權限看）的單：Jira 的批次查詢會默默略過查不到的單，所以同步時沒回來的單會逐張再問一次，確定是 404 才標成查不到（一次同步最多確認 20 張，資訊窗那邊一次 3 張，剩下的下次同步再確認；連不上 Jira 時什麼都不標）。標了以後那一列的狀態是紅色的「Jira 查不到」，留著最後一次讀到的資料，估點、換狀態、兩種寫回都停用，等著寫回時數的也取消；它仍算在這一期的數字裡，因為沒有權限和被刪除在 Jira 看起來一樣，要不要拿掉由你決定。之後 Jira 又查得到的話，把單號再加一次就恢復。每列最右邊的 ✕ 把那張單移出這一期（`ticket.remove`）：只改這一期的清單，工單資料、工時紀錄、綁定都不動，不連 Jira；那張單在這一期有工時會提示一句（移出後不算進這一期的投入，加回來就恢復）；它在 Jira 還貼著本期標籤的話，下次同步會自己回來。已轉派的單：同步時會讀每張單的負責人，並問 Jira 一次「我是誰」（`/rest/api/3/myself`），用帳號 ID 比對，不比名字。負責人不是你的單，在那一列寫「已轉派給 XXX」；Jira 上沒有負責人的寫「沒有負責人」。問不到你的帳號時，這次一張都不標，並提示一句。Jira 回應裡沒有負責人欄位（例如沒有權限看）時當成不知道，也不標。比對用的是上次同步讀到的負責人。已轉派、還沒完成、這一期沒有你的工時、不是你手動加進這一期（這版之後才記）、也沒有按過「略過這張」的單，工單表上方會問「有 N 張單在 Jira 已轉派給別人，要移出本期嗎？」。每張單都可以按「略過這張」（留在本期，這一期不再問，`ticket.keep`）；按「移出這 N 張」會再確認一次，然後一起移出（`tickets.remove`，跟 ✕ 一樣只改這一期的清單，全部單號都在這一期才會移）。其他已轉派的單（已完成、有工時、手動加的、略過的）和沒有負責人的單只標記，不會問。預設的同步條件只抓負責人是你的單，所以移出的單不會被下次同步加回來。寫回估點、實際點數、實際時數時，Jira 如果回「Field … cannot be set. It is not on the appropriate screen, or unknown.」，面板會先用中文說明是這張單的專案或類型沒有那個欄位，原文附在後面。
5. 計時：資訊窗 Sprint 區塊的 ▶ 替這個 session 綁的單或工作項目開始計時（實體會議、離開電腦的討論），⏸ 停止就記成一筆「計時」手動時段（綁單號的依綁定比例分給各單、寫行事曆；綁工作項目的記成「沒有單號的工作」，說明是工作項目名稱，不寫行事曆）；計時中那列每秒走，剩餘時數跟著倒數。超過 24 小時只記 24 小時，不到 1 分鐘不記。session 結束（cubi 不再回報它、Claude Code 也不再列出它）15 分鐘後還在計時，就在它最後活動的時間自動停；只是放生或閒置的 session 不會被停。同一段時間只算一次：這版之後記下的計時整段算，同時段 session 自動記的時段讓出那段時間（之前記下的計時照舊，讓給自己 session 的時段）；行事曆上跟自己 session 的事件不重疊。面板「總覽」最上面列出所有計時中的，也能停。
6. 綁定：session 名稱、git 分支、cwd 裡的單號自動綁；資訊窗的「綁單號…」與每張單那列尾端的 ✕ 直接改（資訊窗最多列 8 張，多的寫「還有 N 張」；面板「綁定總覽」列出這個 sprint 有活動（或正在計時、或面板就是從它開的）的 session 綁的單與比例，任一張都能解）；計時停下來時依「那一刻」綁的單與比例分（誤解綁再綁回不會白跑），全部解掉就照樣計時、停下來不記（按鈕寫「不記」）；在面板拿掉的不會再自動加回；一個 session 綁多張單時時數預設平分，比例可改（「套用比例到本 sprint」會回算已過的段）。
7. 時數：
   - session 活動時段依比例分攤給綁的單；手動時段整段算；手動優先：補記時間與計時（這版之後新增的）所記的那段時間，會從同時段所有 session 自動記的時段扣掉，不管那個 session 綁哪張單或工作項目、這筆補記算不算進投入（例如記一段休息，那段時間就不算進任何單），被扣到或還回時間的單在開了「自動寫回時數」時會重新寫回 Jira；兩個 session 同時在跑彼此不扣，兩邊都算；之前的紀錄不受影響（行事曆目前還是照舊寫 session 的時段，可能跟同時段的會議事件重疊）。
   - 另外，同一張單的同一段時間只算一次（這版之後新增的紀錄才這樣算：先記的照算，後記的只補沒被算到的部分；同一時刻這張單從各紀錄分到的比例加起來最多 100%，例如兩個 session 各分 50% 就算滿；這條只比同一張單：兩個 session 各做不同的單時兩邊都算，因為可以同時做好幾張（手動優先那條例外）；之前的紀錄與已寫進 Jira 的實際時數照舊，不回頭重算），時段清單會標「重疊 N 不算」或「跟其他紀錄重疊」；種類是會議／討論的另計「會議時數」。
   - 「沒有單號的工作」卡片記沒有 Jira 單的時間（PM 開的異常會議、支援、面試…），每一筆都掛在一個工作項目底下（工作項目就是沒有單號的單，跟工單同一層；它的時數＝綁了它的 session 自動記的＋它底下的補記與計時）：掛在開始時間落在的那個 sprint（都沒落在就掛目前的）；工作項目設成「算進 sprint 投入」的才算進「投入」（會議類也算進「會議」），不算進任何一張單、不影響實際／估點比例與容量；補記可以勾寫進行事曆（標題＝工作項目名稱＋說明＋種類）。這版之前記的、沒有掛工作項目的補記照舊（時數、算不算進投入、行事曆都不變），列表上標「未歸屬（改版前記的）」，一樣能改能刪。
   - 行事曆：收掉的段（標題＝單號＋session 名）與勾了的手動時段。
   - 沒有單號的工作算在哪一期是每次照開始時間對各期日期算的（補記之後才建的那一期也會拿到落在它日期裡的時段）；沒有任何一期涵蓋那個時間才用記下時的那一期。
   - 時數的表單都用小時（可以有小數）。「補記時間」表單一定掛在某個工作底下：工單那列的「＋」只記到那張單（標題「補記時間：單號」）；下方「工作項目」每一列的「＋」只記到那個項目；卡片右上的「新工作項目」先取名（規則同綁定：不能像單號、最多 24 字；已有的名字會擋下來，請你用它那一列的＋）、可勾「算進 sprint 投入」（預設不勾，是整個項目的設定，不是這一筆的），再記第一筆。表單底下會提醒「同一段時間有 session 在跑的話，以這筆為準」。
   - 加完右下角只說一句：記了哪一段（起訖時間）、這筆算不算進投入（不算時寫原因：單不在那一期工單裡，或工作項目沒勾「算進 sprint 投入」；落在別期或不在任何一期也會說），以及正在看的這一期投入記之前→之後與差多少（兩邊照面板顯示到分鐘；沒變就寫「投入不變」）。有被扣的時間時，這句底下多一個「明細」，點開才列：哪幾張單或工作項目 session 自動記的時間被扣了多少（補記自己掛的那張單或那個項目不算被扣；精確到秒），分成三段、沒有的不寫：算在那一期投入的（那一期工單清單裡的單、算進投入的工作項目）、不在那一期工單（或那段時間落在別期日期，例如補記跨過兩期交界）的單、不算進投入的工作項目，後兩段不影響投入；補記蓋到自己那張單或那個項目的 session 時，另寫「其中 X 原本就算在那裡（session 或之前的補記），同一段時間不重複算」（所以投入增加的會比記的少）；再寫投入精確到秒的差（被扣不到 1 分鐘的不列，有這種情況時會註明加起來多少、其中多少算在投入裡，算在投入的那部分在這個差裡）（開了自動寫回時數時也說會重送這些單的 Jira 工時）。有明細、落在別期或這筆不算進投入時，這句會留著直到按 ✕，其他的 4 秒後消失。那段時間不在正在看的這一期時，那一句會說算在哪一期（切過去就看得到），沒有任何一期涵蓋它也會說；這不是錯誤，不用紅底。
   - 工單的：第一排是時數和種類（預設「會議」），不開「進階」就是剛剛結束、往前推那麼久（正在看的不是現在這一期時，會說算在哪一期）；「進階」裡是開始時間、備註、要不要寫行事曆，開始時間打開時已經填好「現在往前推所填時數」，只要改時分，沒動過它之前改時數它會跟著變，「現在」鈕填回這個值；開始時間清空或只填一半會擋下來，不會偷偷改成別的時間。工作項目的：開始時間一直看得到，規則相同，說明選填（例如 code review）；算不算進投入看工作項目的設定，每一筆不能各自勾。
   - 工作項目：按「新工作項目」，或在 session 的綁定框（面板或資訊窗的 ＋）填一個不是單號的名字（例如「小工具開發」），就把 session 綁到這個自己取名的工作項目；跟單號只能二選一（已綁單號就要先解除，反過來也一樣，session 名稱或分支裡的單號在綁著工作項目時不自動綁），名字不能長得像單號、最多 24 字。綁了工作項目的 session，自動記的時間和計時都算「沒有單號的工作」：卡片裡多一列「本期自動記的」（扣掉補記與計時重疊的部分），下方「工作項目」列出每個項目、幾個 session 綁著、本期時數（自動記的＋補記＋計時）、「算進 sprint 投入」勾選（預設不算）和補記用的「＋」；改這個勾選會套用到這個項目「現在所在這一期」的全部時間（自動記的時段、補記和計時，以開始時間算在哪一期）以及之後記的，過去幾期不變（現在不在任何一期時，套用到正在看的那一期），改完右下角會說改了哪一期多少時間。一個 session 只能綁一個工作項目：已綁「X」時再填別的名字會擋下來，要先解除。沒有起訖日期的 sprint 不收工作項目的自動時間。工作項目只存在這台電腦（`sprints.json`），不寫 Jira；session 自動記的時間不寫行事曆，補記勾了才寫。
   - 名字只差大小寫算同一個工作項目：綁定框打「cubi」會綁到已有的「Cubi」，「新工作項目」打已有的名字（大小寫不同也算）會擋下來，請你用它那一列的＋。
   - 工作項目那一列的鉛筆是改名：規則同上，它底下的補記與計時、綁著的 session、session 自動記的時間一起改過去，時數和算不算進投入不變；行事曆上已寫的事件標題不會跟著改。改成另一個已有的名字（大小寫不同也算）就是把兩個併成一個，用已有那個的名字和設定：現在這一期裡併進來的時間改用它的「算進 sprint 投入」，之前各期照舊；併之前會先說會怎樣、按「確定合併」才併，併了分不開。
   - 那一列的 ✕ 是刪除：先在底下列出會一起刪掉什麼——底下的補記（哪幾期各幾筆）、session 自動記到它的時間（拿掉後不算進任何地方）、要解除幾個 session 的綁定、各期投入會從多少變多少、其中哪幾筆補記勾了寫進行事曆——按「刪除…」再按「確定刪除？無法復原」才刪；正在計時的擋下來，先停計時。有 session 這 10 分鐘內還在用這個項目時，確認框最上面用紅字列出它的名字：刪掉後它這一段之後的時間不會算進任何地方，要等它停 10 分鐘以上、下一段開始才恢復（即使你馬上把它改綁到單上），因為每一段時間都照它開始時綁的東西算。
   - 綁過工作項目的時段（包括項目已刪掉的），在分攤按「套用到整期」時不會改成單號的分攤（之前會讓同一段時間在工作項目和單上各算一次）。
   - 刪除或合併之前，插件會把 `sprints.json`、`bindings.json`、`segments.json` 複製到插件資料目錄的 `backups/<時間>-item-delete/`（合併是 `-item-merge`），留最近 20 份，完成的訊息會寫出備份在哪；要退回去就關掉 Cubi、把那三個檔複製回資料目錄（之後記的會一起不見）。
   - 已寫進行事曆的事件不會跟著刪，要自己到行事曆清：刪工作項目、或在列表上按 ✕ 刪一筆勾了寫行事曆的補記時，會列出那幾筆的日期、時段和標題。
   - 命令列：`item.rename`（`name`、`to`；併進已有的項目要再加 `confirm: true`）、`item.delete`（`name`；不加 `confirm: true` 只回傳會刪掉什麼）。
   - 點工單的時數展開明細，每一筆手動時段旁邊有「改」和 ✕；明細底下另列這張單「不在本期期間的紀錄」（例如在這一期畫面補了「剛剛結束」、其實落在下一期的），寫出落在哪一期（或不在任何一期），一樣能改能刪；一張單在這一期沒有工時、只有別期紀錄時，時數那格是「別期 N 筆」，點開就看得到。底部「手動時段」卡一樣能改能刪，不在本期期間的那幾筆會標灰字。同一張單重疊的部分會寫出多少不另算。
   - 工單列最右邊的 − 是「移出這一期」，按了會先在那一列問一次（工時不會刪，Jira 還貼著本期標籤的話下次同步會再加回來）。
   - 沒預料到的錯誤會顯示「內部錯誤，請把這段訊息截圖給 RD：…」。
   - 命令列一樣：`time.add` 有 `key` 而沒給 `start` 就是剛剛結束；沒有 `key` 時要給 `item`（新的項目另給 `newItem: true`，可加 `itemCounted`）。
   - 已經記下的手動時段在「手動時段」與「沒有單號的工作」裡按「改」可以改時數、開始時間、種類、備註（`time.update`，只送有改的欄位）；計時記下的那種只能改長度或刪除，因為它的分鐘數要跟同一個 session 自動記的時段對起來。行事曆不會跟著改：Cubi 對自己寫過的事件只會延長，所以除了「48 小時內的時段單純變長」之外，改過一筆有寫進行事曆的時段後面板會提醒你手動調整或刪除舊事件。
8. 「回顧」：五張數字卡、任務分類甜甜圈（提早／準時完成、超時完成、未完成、超時未完成、未估點；點一類列出那些單）、burndown、近幾個 sprint、總結與四段文字＋感謝（一行一條，離開欄位就存）、「匯出 Markdown」。「用 Claude 整理」把數據寫成插件資料目錄底下的 `briefs/<標籤>-data.md`，在設定的資料夾開一個 Claude Code session，請它寫好四段後用 `<cubi 的完整路徑> --tool-run sprint review.update '<JSON>'` 這一條指令填回面板。這個 session 一律用受限模式開（資料檔裡有 Jira 上別人寫的原文，放在兩行 `<<<第三方資料…>>>` 記號之間）：它只讀資料檔、用那一條 `review.update` 指令寫回面板，不寫檔，而且不會問你任何事——寫回這一步不經過你核准，其他指令一律跑不了（最壞的情況是面板上的回顧文字被寫成奇怪的內容，重按一次就蓋掉）；開啟後 3 分鐘還沒收到回顧，面板右下角會提示你去終端看那個 session（它的寫回指令寫錯被拒時，這邊不會有別的訊號），請它照資料檔的寫法重寫；收到後提示就換成「Claude 寫回來了」。要 Markdown 就按面板的「匯出 Markdown」。資料檔寫在插件自己的資料目錄 `~/Library/Application Support/cubi/sprint/briefs/`，不寫進你的回顧資料夾。review 提醒：每一期在 review 日的行事曆上有一筆「Sprint review」（時間與長度在設定頁，預設 10:00、30 分鐘；時間留空就不寫）。這筆事件每期只交給 Cubi 寫一次——從該期第一天起的第一次定時執行，之後 10 分鐘內重送同一筆（補掉一時寫不進去的情況），然後不再送，所以你可以把它拖到實際開會的時間、搬到別本行事曆或刪掉，不會再長一筆；改設定只影響還沒寫出事件的期。行事曆上沒看到（當時還沒授權行事曆）就按面板提醒旁的「重新寫入行事曆」，下一分鐘照現在的 review 日與時間再寫一次；舊事件若被移動過或 review 日、時間改過，會多出一筆，要手動刪舊的。事件寫出後又改了那一期的結束日，行事曆上的事件不會跟著動，面板會提醒一次。review 日當天資訊窗的 Sprint 區塊第一列是「今天 review」（那天工單最多列 7 張）；從 review 日到那一期最後一天，總覽最上面有提醒與「產生回顧」。匯出的 Markdown 與交給 Claude 的資料檔第一段都寫「產生於 …，數字截至這個時間」，之後記的工時只會出現在面板上。
9. AI 估點：設定頁「AI 估點」區有「預設的程式碼資料夾」與「各專案的程式碼資料夾」（每個專案代號一列，可按「選資料夾」；專案清單是設定的專案 key、本期工單的前綴與已設定過的）。一張單用它專案代號的資料夾，沒設就用預設資料夾；兩邊都沒有，那張單的 ✨ 是灰的並寫「WEB 還沒指定程式碼資料夾」（存檔時每個填了的資料夾都要存在，而且不能是根目錄、家目錄或它的上層，也不能是放金鑰與憑證的資料夾（.ssh、.aws、.gnupg、.kube、.docker、.config/gcloud、.config/atlassian、Library/Keychains）、它們底下或它們的上層（例如 ~/.config、~/Library），比的是資料夾本身（不看路徑寫法，所以大小寫、symlink、/System/Volumes/Data 開頭的寫法都繞不過）；開 session 時再檢查一次，手改設定檔也擋得住；空的那列會拿掉），工單表每列多一顆 ✨。按下去，插件先向 Jira 讀這張單的摘要、類型、狀態、描述，連同目前估點、已投入時數、本期其他已估點的單（當尺度參考），寫成 `briefs/<單號>-estimate.md`，再在那個資料夾開一個受限的 Claude Code session：它讀資料檔與資料夾裡的程式碼，只能用 `<cubi 的完整路徑> --tool-run sprint estimate.suggest '<JSON>'` 這一條指令交回點數、把握（高／中／低）與兩三句理由，而且只收面板剛開過資料檔的那張單；找不到相關程式碼時要在理由裡講明、把握寫低。Jira 上的工單內容放在兩行 `<<<第三方資料…>>>` 記號之間。建議出現在那一列底下：按「採用」走跟手動改估點一樣的寫回，只把點數寫進 Jira；按「不要」就清掉，什麼都不送。還沒按「採用」或「不要」之前，可以在那個 session 裡追問、請它重送，新的建議會蓋掉舊的（第一筆回來後面板仍每 30 秒看一次，看到新的就換上並提示「AI 估點更新了」，直到按了「採用」或「不要」、或開始等之後滿一小時）；按了之後就不再收，採用後想改，直接在面板改估點，或再按一次 ✨ 重估（新的資料檔會寫上目前的估點）。設定頁的「補充估點規則」（500 字內，不能有 `<<<` 或 `>>>`）會原樣、每行前面加 `> `，放進資料檔「怎麼估」那一節的最後，在別人寫的原文記號外面；它只改估法，改不了 session 能讀什麼、能跑什麼；留空時資料檔跟沒有這個設定時一字不差。理由只存在這台電腦、只在面板顯示，不送 Jira。等待方式跟「用 Claude 整理」一樣：每 30 秒看一次，3 分鐘沒收到就在右下角提示去終端看（同時等好幾張時，提示列出還沒回來的那幾張）；同時最多等 3 張，每一張都追到回來、按「不等了」或滿一小時為止，回來幾張就在右下角一起說（「PROJ-2 的 AI 估點回來了（還在等 2 張）」），等待中每張都可以各自按「不等了」；已經有 3 張在等時 ✨ 是灰的。工單表右上的「多張 AI 估點」：勾要估的單（最多 3 張，已在等的也算在內，勾滿了其他勾選框變灰），按「開始估（N 張）」後一張一張開，每一張都會跳一次 Cubi 開 session 的確認；取消其中一張就停在那裡，後面的不開，右下角說「開了 X 張的 AI 估點，其餘 Y 張沒有開」。勾選時星號那一欄換成勾選框。開 session 失敗或在確認框按取消，那張單不會留在「估點中」；同一張單在等的一小時內 ✨ 是灰的（「已在估，要重開請先按「不等了」」），連點也只會開一個 session，超過一小時視為那個 session 不會回來了，可以重開；已經有建議的單可以直接重估。**這個資料夾裡的檔案 Claude 都讀得到**（受限模式只擋工作目錄以外的讀取，擋不了資料夾裡的 `.env` 之類），請勿選含機密的資料夾。
10. 沒有估點欄位的單（專案或單的類型的編輯畫面上沒有那個欄位）：改估點或按「採用」時照常先寫欄位；Jira 回 400，插件再讀這張單的 editmeta（編輯畫面有哪些欄位，看欄位 id，跟 Jira 的語系無關），確定沒有估點欄位才在那一列底下問你，其他情況（欄位其實在、editmeta 讀不到、網路或權限錯誤、清空估點）照原本的錯誤顯示。那一列給出整則留言的原文：只有整句粗體的「【估點】本單 N 點（1 點＝1 人天）」，不放 AI 的理由；三個按鈕：「留言到 Jira」才會寫、「只記在本機」只存這台電腦（例如你已經自己留過言）、「取消」什麼都不動。Cubi 記得自己發的那一則留言的 id，之後改估會編輯那一則，不碰別人或你手寫的留言；改之前那一列會顯示 Jira 上目前的文字，被改過會特別說；那則留言被刪了，那一列會說會發一則新的，按下才發；在你看到確認列之後才被刪的，按下時什麼都不寫，改成問你要不要發新的。這些單的估點存在本機，同步不會蓋掉（Jira 沒有值）；不會從留言讀回估點。估點格滑過去會說它記在留言還是只在本機。
11. 資料：`~/Library/Application Support/cubi/sprint/`（config、sprints、tickets、bindings、segments，都是 JSON）。`make plugin-test` 跑它的測試。
